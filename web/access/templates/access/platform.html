One pipeline, end to end

drop a file, and the answers rebuild themselves
  1. Sources MACL traffic · Avas rides · FollowMe GPS · MTCC ferries · Census 2022 · MoE statistics · MoH facilities · OCHA boundaries
  2. Ingest each source group is fingerprinted (sha256 of path, size, mtime); only the stale stages re-run, and the whole plan is printed before it runs
  3. Derived tables island spine · sea network from GPS · school provision from the MoE PDF · service access · placement ranking
  4. SQLite one file, data/platform.sqlite, with the pipeline stages exposed as views so the app never reads a CSV
  5. App map · services register · placement simulator, all served from the database

What makes it a platform, not a dashboard

  • Any service category. Services live in one register with a category and a type; the map, the card and the simulator all read the category. Education and health are just the first two.
  • Any dataset drop. New MACL, Avas, FollowMe or MTCC files are picked up by fingerprint — nothing is hard-coded to a filename or a date range.
  • A database, not a folder of CSVs. The app opens data/platform.sqlite read-only; the pipeline rebuilds it atomically.
  • One network. Sea crossings, the Addu causeway and (next) domestic air all feed the same Dijkstra, so a new service type costs one register row, not a new model.
  • A decision tool. The simulator answers "where should the next hospital go?" with people and children connected, not with a heat map.

How to run it

make setup          # python deps
make external       # Census, OCHA, MoE, MoH
python3 scripts/ingest.py        # build everything
python3 scripts/watch_data.py    # optional: rebuild on new files
cd web && python3 manage.py runserver

Every stage is idempotent, every published number is asserted by scripts/check_outputs.py, and the footer of every page shows when the data was last built.
